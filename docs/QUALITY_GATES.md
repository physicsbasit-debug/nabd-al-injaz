# ضمان الجودة | نبض الإنجاز

## قواعد الاعتماد
- العمل على فرع مستقل، وفتح Pull Request قبل الدمج في `main`.
- GitHub Actions يشغّل ESLint وفحص تنسيق الملفات الجديدة واختبارات Node وVitest والبناء واختبارات Playwright.
- تشمل اختبارات المتصفح الحاسوب والهاتف، وفحص الوصول باستخدام axe-core، وصور الحالات الأساسية للواجهة.
- تُراجع صور `playwright-evidence` بصريًا قبل اعتماد أي تعديل في التصميم. **الصور الحالية أدلة للمراجعة وليست مقارنة بصرية آلية مع خط أساس معتمد بعد.**
- بعد اعتماد صور مرجعية ثابتة، يمكن إضافة `toHaveScreenshot` إلى اختبارات Playwright لجعل الفروقات البصرية شرط نجاح آلي.
- لا تُغيّر بيانات المهام أو ربط Supabase ضمن هذه المرحلة.

## تنسيق الملفات
- `npm run format`: تنسيق جميع الملفات المدعومة عند اعتماد دفعة تنسيق مستقلة.
- `npm run format:check`: يتحقق حاليًا من ملفات ضبط الجودة الجديدة. ملفات الواجهة القديمة لم تُنسق جماعيًا لتجنب تغييرات واسعة غير وظيفية.

## حماية main
في المستودع الخاص الحالي لم تسمح خطة GitHub المجانية بتفعيل Branch Protection (HTTP 403).
لذلك يبقى منع الدمج تلقائيًا غير مفعل، ويجب اعتماد قاعدة تشغيلية: لا دمج قبل نجاح Verify والمراجعة البصرية.
لا يُنصح بجعل المستودع عامًا فقط من أجل الحماية.
