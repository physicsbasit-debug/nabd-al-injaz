# نبض الإنجاز: عقد مكتبة الخطط ومؤشرات الإنجاز | 2-B0

**الحالة:** اعتماد المستخدم لطريقتين متكاملتين: رفع ملف الخطة واستخراج أنشطتها للمراجعة، والإدخال اليدوي. هذه وثيقة مواصفات فقط، وليست إعلان تنفيذ.

## نطاق الخطط
- خطة المادة.
- الزيارات الإشرافية.
- الزيارات المتبادلة.
- الإنماء المهني.
- الاجتماعات الدورية.
- رفع المستوى التحصيلي.
- خطط مخصصة غير محدودة الاسم، ويمكن إنشاء أكثر من خطة من النوع نفسه.

## نموذج البيانات
- الخطة: معرّف ثابت، اسم، نوع أو اسم نوع مخصص، الفترة، المسؤول، حالة فعالة/مؤرشفة، تاريخ الإنشاء والتعديل، مصدر يدوي/مستورد/مختلط، ومراجع الملفات.
- النشاط: معرّف، معرّف الخطة، عنوان، وصف، مكلف، موعد استحقاق، حالة لم يبدأ/قيد التنفيذ/مكتمل، تاريخ إنجاز فعلي، مراجع الشواهد، مصدر الإدخال، ومرجع صف/صفحة عند الاستيراد.
- الشاهد: معرّف، معرّف النشاط، اسم الملف ونوعه وحجمه وتاريخ إضافته. لا تحفظ الملفات الثنائية داخل localStorage؛ تُحدد آلية تخزين محلية مناسبة مع النسخ الاحتياطي قبل التنفيذ.
- البيانات مستقلة عن مخزن المهام العامة الحالي ولا تغيّر عقوده أو بياناته.

## طريقتا الإدخال المعتمدتان
1. **يدوي:** إنشاء خطة ثم إضافة نشاط بعنوان وموعد ومسؤول ووصف؛ تبدأ حالته بلم يبدأ.
2. **استيراد:** رفع Word DOCX أو Excel XLSX أو PDF نصي؛ تحليل محلي دون إرسال البيانات لخادم خارجي؛ عرض معاينة الأنشطة المقترحة ومصدر كل نشاط، مع تعديل أو استبعاد الصفوف، ثم زر صريح لاعتماد الأنشطة المحددة.
3. يجوز الجمع بين الاستيراد واليدوي داخل الخطة الواحدة. لا يغير الاستيراد بيانات الخطة قبل الاعتماد.
4. الاستيراد البنيوي ليس فهمًا مضمونًا لكل قالب، ولا OCR تلقائيًا. ملفات PDF المصورة قد تتطلب إدخالًا يدويًا. لا تُخترع أنشطة أو تواريخ أو أسماء عند غموض الملف.
5. التحقق من نوع الملف وحجمه، والتواريخ الملتبسة، والتكرارات، ومنع تشغيل محتويات الملفات، وتأكيد المستخدم قبل دمج أو استبدال سجلات موجودة.

## قواعد المؤشرات
- لكل خطة فعالة بطاقة مستقلة في الصفحة الرئيسية، ولا تخلط مؤشرات الخطط مع نسبة المهام العامة.
- إجمالي الخطة = عدد الأنشطة المعتمدة فقط، والمكتمل = عدد الأنشطة المعتمدة المكتملة.
- نسبة الإنجاز = تقريب (100 × المكتمل ÷ الإجمالي). إذا لم توجد أنشطة معتمدة تعرض عبارة «لا توجد أنشطة معتمدة» ولا تعرض 0% مضللة.
- المتأخر = نشاط غير مكتمل بتاريخ استحقاق صحيح يسبق التاريخ المحلي الحالي؛ نشاط اليوم ليس متأخرًا.
- «مكتمل» غير «موثق»: الإنجاز دون شاهد يُحسب مكتملًا، مع تنبيه «ينتظر التوثيق». الموثق فقط ما أُرفق له شاهد.
- جميع الأنشطة متساوية الوزن مبدئيًا. لا تفعيل للأوزان دون اعتماد قاعدة محددة.
- لا تُحسب النسبة من رفع الملف، ولا من عدد صفحاته، ولا من مسودات الاستيراد.
- مثال توضيحي لا يمثل بيانات حقيقية: 8 أنشطة مكتملة من 12 معتمدة = 67%.

## تصميم الصفحة الرئيسية
- عنوان «متابعة تنفيذ الخطط» وشبكة بطاقات لكل خطة فعالة.
- البطاقة: اسم الخطة، النسبة أو رسالة عدم وجود أنشطة، المكتمل/الإجمالي، المتأخر، والمنتظر للتوثيق.
- الضغط يفتح صفحة أنشطة الخطة وتواريخها ومسؤوليها وشواهدها.
- زر «إضافة خطة» مع خيار إنشاء يدوي أو رفع ملف.
- إمكانية الأرشفة دون حذف سجل الخطة.
- مؤشرات المهام العامة الحالية تبقى مستقلة.

## ترتيب التنفيذ دون تجاوز المراجعة
- **2-B0 (الحالية):** مواصفات واعتماد شكل الواجهة وتدفق إدخال الخطة. لا دمج.
- **2-B1:** مكتبة خطط يدوية، إضافة وتعديل وأرشفة الأنشطة والخطط، تخزين محلي بإصدار، مؤشرات مستقلة واختبارات الحساب وعدم فقد المهام القديمة.
- **2-B2:** استيراد XLSX ثم DOCX ثم PDF النصي؛ مراجعة المقترحات والاعتماد ومنع التكرار. اختبار كل صيغة بعينة حقيقية قبل إعلان دعمها.
- **2-B3:** الشواهد، تخزينها المحلي الآمن والنسخ الاحتياطي، التمييز بين الإنجاز والتوثيق، ثم التقارير.
- **2-B4:** اختبار شامل ولقطات فعلية للهاتف والحاسوب ومراجعة المالك ثم الدمج.

## شروط القبول
1. لا نسب وهمية أو نشاط مخترع.
2. كل خطة تُحسب وحدها من أنشطتها المعتمدة.
3. المتأخر والمكتمل والموثق مفاهيم مستقلة ومحددة.
4. الاستيراد لا يغير البيانات قبل المراجعة والاعتماد.
5. الدمج بين الإدخال اليدوي والاستيراد لا يفقد أي نشاط.
6. لا تراجع في مهام المرحلة الأولى أو واجهة PR #4.
7. RTL واختبارات الهاتف والحاسوب والحسابات وتوافق البيانات القديمة.
8. لا Supabase ولا خدمات ذكاء اصطناعي خارجية في هذه المرحلة.
9. لا دمج إلى الفرع الرئيسي دون اعتماد المالك.
