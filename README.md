# نبض الإنجاز

منظومة مستقلة لإدارة أعمال المعلم الأول.

**الحالة:** نموذج محلي تشغيلي للخطط والمهام والشواهد والجداول والمتابعة الفنية. بيانات المتابعة الفنية تُدخل من النشرة الفعلية يدويًا وتُحفظ على الجهاز؛ الربط الخادمي والصلاحيات والإرسال الآلي لم تُنفذ.

## النطاق

- لوحة مهام يومية ونسب إنجاز محسوبة.
- الخطط ومتابعة الإنجاز والشواهد.
- جداول Excel للمعلمين، ومعرفة المتفرغ حسب اليوم والحصة.
- مسودة توزيع احتياط يدوي أو آلي مع منع التعارض ومراعاة الاستثناء والرصيد؛ اعتماد التكليف ورسائل واتساب يبقيان بيد المستخدم.
- مراجعة الاختبارات القصيرة ومطابقتها لوثيقة التقويم.
- النشرة التوجيهية وتقدم تنفيذ المناهج حسب المعلم والمادة والصف، دون إدخال لكل شعبة.
- الصف الثامن: العلوم 6 حصص أسبوعيًا؛ الصفان التاسع والعاشر: الفيزياء والكيمياء والأحياء حصتان أسبوعيًا لكل مادة.
- الإنماء المهني وحضور المعلمين.
- روابط رفع إنجازات المعلمين، ومراجعتها واعتمادها.
- تقارير مستمدة من السجلات الفعلية.

## المبادئ

واجهة RTL احترافية، خطوط عربية واضحة، أكورديون منظم، مؤشرات دائرية، بنية قليلة التعقيد، لا نسخ من مسار، ولا خدمات مدفوعة في البداية.

## المرحلة الحالية

توزيع احتياط يومي في مرحلة التشغيل التجريبي: تسجيل الغياب، اقتراح بدائل وفق الرصيد والقسم وعبء اليوم، منع التعارض، مراجعة التكليفات، وحفظ معالجة اليوم وسجله. التوزيع مسودة للمراجعة اليدوية؛ لا يرسل تكليفًا ولا يعتمد رسميًا تلقائيًا. المتابعة الفنية فعّالة لإدخال موضوعات النشرة وتسجيل الحصص المنفذة ومتابعة المواعيد؛ لم تُضف بيانات منهج افتراضية. الاختبارات والتحصيل، الإنماء المهني، التقارير، والمزامنة الآمنة بين الأجهزة مراحل لاحقة.

## GitHub Pages

يحتوي هذا المستودع الواحد على المصدر وسير عمل البناء والنشر إلى GitHub Pages. عند الدفع إلى `main`، يبني GitHub الموقع من `src/` وينشر مجلد `dist/` مباشرة؛ لا حاجة إلى مستودع نشر منفصل. رابط Pages هو `https://physicsbasit-debug.github.io/nabd-al-injaz/`. لا يُضمّن ملف Excel أو سجلات المدرسة في البناء. تبقى البيانات في المتصفح الحالي دون مزامنة تلقائية؛ من الصفحة الرئيسية يمكن تنزيل ملف نسخة كاملة ونقله يدويًا إلى جهاز آخر ثم استعادته. يحتوي ملف النسخة على بيانات مدرسية خاصة، لذا يُحفظ في مكان موثوق.

## القادم

التحقق من ترتيب المقترحات على عينة المدرسة ثم توسيع بقية الأقسام حسب خارطة المراحل. يعمل فحص Playwright في GitHub Actions على كل طلب دمج وتغيير إلى `main`. النسخة الاحتياطية تنقل البيانات يدويًا؛ المزامنة التلقائية تتطلب ربطًا خادميًا بصلاحيات معتمدة.
